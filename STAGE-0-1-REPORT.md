## Этап 0. Каркас и инфраструктура

### Что сделано

**Репозиторий.** `backend/` (Python 3.10+, FastAPI), `frontend/` (React 18 + TypeScript + Vite),
`data/` (БД и артефакты), `tools/` (служебные скрипты), `run.ps1` (запуск одной командой).

**Конфигурация** — `backend/app/core/config.py`. Все настройки через переменные `UPA_*` и
`.env`; секретов в коде нет. Два неочевидных решения:

- `absolute_database_url` — путь к SQLite приводится к абсолютному. Относительный путь
  SQLite разрешает от текущего рабочего каталога процесса, поэтому при запуске из
  `backend/` (так делают CLI и Alembic) приложение открывало бы другую БД. Это была
  реальная ошибка, пойманная при проверке.
- `UpaEnvSettingsSource` — отключает JSON-разбор для `UPA_CORS_ORIGINS`, чтобы привычная
  запись через запятую не падала с ошибкой разбора.

**Логирование** — `structlog`: человекочитаемо в dev, JSON в prod.

**Ошибки** — единый формат `{"error": {"code", "message", "details"}}` для всех сбоев,
включая необработанные исключения и ошибки валидации.

**База данных** — SQLAlchemy 2.0 async + SQLite (WAL, включённые внешние ключи).
8 таблиц конвейера: `sites`, `snapshots`, `element_maps`, `scenarios`, `scenario_versions`,
`runs`, `run_items`, `artifacts`. Миграции — Alembic, `0001_initial` применена.

**API** — 24 маршрута, доступны и с префиксом `/api/v1`, и без него (второй набор нужен
скрипту запуска). Интерактивная документация — `/docs`.

**Фронтенд** — каркас с боковым меню и шестью разделами: Обзор, Сайты, Карта элементов,
Сценарии, Запуски, План работ. Обзор и Сайты работают с настоящим API; остальные —
заглушки с указанием этапа.

**Запуск** — `run.ps1`: создаёт venv, ставит зависимости, инициализирует БД, проверяет
Ollama (не блокируя запуск при её отсутствии), поднимает API и Vite, останавливает оба
процесса по Ctrl+C.

**Тесты и линтеры** — 54 теста (pytest + httpx ASGI), `ruff` и `black` без замечаний,
GitHub Actions проверяет бэкенд и фронтенд.

## Этап 1. Браузер и снапшот страницы

### Что сделано

**Браузерный движок** — `backend/app/crawler/browser.py`. Открывает URL в Chromium,
ждёт `networkidle` плюс настраиваемую паузу (страницы успевают дорисоваться скриптами),
закрывает типовые баннеры о cookie, автоматически принимает диалоги. Собирает:

- финальный DOM после JS и `dom_hash` — ключ кэша и признак изменения вёрстки;
- скриншот viewport и страницы целиком;
- сетевые запросы с телами JSON-ответов (ограничение размера настраивается);
- `storage_state` (cookies и localStorage) для повторных заходов;
- ошибки консоли и список неудавшихся запросов.

**Обрезка DOM** — `backend/app/crawler/dom.py`. Ключевой модуль: без него реальный каталог
не влезает в контекст локальной модели. Что делает:

1. вырезает скрипты, стили, SVG, комментарии, base64-данные;
2. пересобирает теги: оставляет значимые атрибуты (`id`, `name`, `class`, `role`, `aria-*`,
   `data-*`, `placeholder`, `href`), выбрасывает `style`, обработчики и мусор; ссылки
   делает абсолютными;
3. **схлопывает повторы на любой глубине**: из 60 одинаковых карточек оставляет 3 и
   вставляет пометку «скрыто ещё 57». Именно это делает возможным анализ каталогов;
4. если результат всё ещё больше лимита — вырезает середину, сохраняя начало (шапка,
   поиск) и конец (пагинация).

**Хранилище артефактов** — `backend/app/crawler/store.py`. Файлы в
`data/artifacts/<id снапшота>/`: `page.html`, `dom-trimmed.html`, `network.json`,
`data-sources.json`, `storage-state.json`, `screenshot.png`, `screenshot-full.png`,
`summary.json`. Запись атомарная (через временный каталог), чтобы прерванный процесс не
оставил «полу-снапшот», который потом молча переиспользуется из кэша.

**Прикладной слой** — `backend/app/crawler/service.py`. Нормализация URL (`example.com` →
`https://example.com/`), запрет локальных и служебных адресов (защита от SSRF, с явным
флагом `allow_local`), создание сайта по origin, кэш по хэшу DOM, фиксация сбоя в
отдельной транзакции.

**API** — `backend/app/api/crawl.py`: снятие снапшота, список, детали, обрезка/полный DOM,
сетевые запросы с фильтром источников данных, скачивание артефактов по белому списку,
удаление, список сайтов.

**Интерфейс** — раздел «Сайты»: поле URL с опцией кэша, список сайтов, список снапшотов,
детальная карточка со статистикой обрезки, таблицей сетевых запросов (JSON-источники
помечены), просмотром обрезанного и полного DOM.

### Доказательства

Все 54 теста проходят, из них 41 покрывают Этап 1:

- **Обрезка DOM** (`test_dom.py`) — удаление скриптов/стилей/SVG/комментариев/base64,
  сохранение значимых атрибутов, абсолютизация ссылок, схлопывание 12 карточек → 3,
  жёсткое ограничение токенов с сохранением начала и конца, извлечение title и meta.
- **Сервис** (`test_crawler_service.py`) — нормализация и валидация URL, запрет локальных
  адресов, сохранение снапшота и восьми артефактов, дедупликация сайта по origin,
  переиспользование кэша, фиксация сбоя, удаление с артефактами, round-trip
  «диск → память».
- **API** (`test_api_crawl.py`) — снятие снапшота, отказ для локальных адресов и неверной
  схемы, списки, DOM в двух вариантах, сеть с фильтром, скачивание артефактов, отказ при
  попытке обхода пути, единый формат 404, кэш, удаление.

Реальный Chromium в юнит-тестах не запускается: съёмка подменяется на уровне
`capture_page`, чтобы тесты были быстрыми и не зависели от сети. Сам драйвер Playwright
проверяется отдельно, настоящим браузером (см. ниже).

### Проверка настоящим браузером

`tools/check_browser.py` поднимает локальный стенд, сделанный «неудобным», как настоящие
сайты: контент дорисовывается скриптом после загрузки, есть баннер о cookie,
12 повторяющихся карточек товара, данные приходят отдельным JSON-запросом. Затем страница
открывается настоящим Chromium через штатный код UPA.

## Как запустить

```powershell
cd D:\Dowland\UniversalParserAutomatization
.\run.ps1
```

Откроется `http://127.0.0.1:5173` (интерфейс) и `http://127.0.0.1:8000/docs`
(документация API). Ollama не обязательна: без неё приложение работает, анализ деградирует
до детерминированных эвристик.

### Проверки

```powershell
# тесты и линтеры
cd backend
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe -m ruff check app tests
..\.venv\Scripts\python.exe -m black --check app tests

# живой API и интерфейс
cd ..
.\.venv\Scripts\python.exe tools\smoke_api.py
.\.venv\Scripts\python.exe tools\check_frontend.py

# съёмка настоящим браузером (нужен установленный Chromium)
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\data\_pw-browsers"
.\.venv\Scripts\python.exe tools\check_browser.py
```

### Доставка зависимостей

В этом окружении `pip install` зависает на сетевой фазе (перебор версий), поэтому в
репозитории лежат `backend/requirements.txt` с точными версиями и
`tools/fetch_wheels.py` — загрузчик колёс, который обходит pip-резолвер и учитывает
только обязательные зависимости. Если обычная установка работает, эти инструменты не
нужны.
